# SOP Book source

The Robot Dolphin Operations Manual is served by Dolphin Apps at **/SOP**
(apps.robotdolphins.org/SOP). Anyone can read it without signing in. Signed-in
team members can press **Suggest an edit** on any SOP, select words and leave a
comment. Mentors review suggestions at **/SOP/suggestions**.

## Folders

| Path | What it is |
|---|---|
| `sops/source/RDOS-SOP-*.md` | The source of every SOP, one file each. The only place SOP text is changed. |
| `sops/sop.css` | The SOP page design (robotdolphins.org palette, ANSI callouts). |
| `sops/build.py` | Turns the source into the web pages. Python 3, no packages needed. |
| `src/sop-content/` | Generated by `build.py web`. Never edit by hand. |
| `src/pages/sop-*.tsx`, `src/components/sop-book/` | The catalog, SOP page, suggest-an-edit UI and mentor log. |
| `convex/sopSuggestions.ts` | Where suggestions are stored (table `sopSuggestions`). |

## Changing SOPs

1. In the suggestions log, accept or reject each suggestion, then press **Copy for Claude**.
2. Give that text to Claude (project "RDOS SOP Creation") with "Apply these SOP suggestions."
3. Claude edits `sops/source/*.md`, then runs:

   ```
   python3 sops/build.py lint   # missing fields, open blanks, unknown sections
   python3 sops/build.py web    # rebuild src/sop-content
   ```

4. Commit `sops/source` and `src/sop-content` together and push (the publish script does this).
5. After the site updates, press **Mark accepted as done** in the log.

Bump `version:` and set `date:` in a source file whenever its content changes,
and add a row to its Revision history table. `status: Approved` only after a
mentor has read the whole SOP.

Internal SOPs (`audience: Internal`) stay in `sops/source` but are left out of the website.

## Source format

Front matter lines (`id:`, `title:`, `dept:`, `style:`, `owner:`, `audience:`,
`summary:`, optional `version:`, `date:`, `status:`, `approver:`, `applies:`,
`link: Text | https://...`), then `##` sections. RDOS-SOP-ORG-000 lists every
pattern (KEY:/GO: steps, `- [ ]` checklists, DANGER/WARNING/CAUTION/NOTICE/TIP
callouts, CARD:, role tags, `[EDIT: ...]` blanks and so on).

Suggestions are pinned to blocks by an anchor like `pre-use-check:4`
(section id, then block number within the section). Rebuilding a page can move
anchors, so the log also keeps the quoted words and a readable label.

## Sharing the book with another team

`python3 sops/build.py export` writes a standalone public copy of every page
plus a zip to `sops/dist/` (ignored by git).
